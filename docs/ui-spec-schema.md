# SketchCode UI Specification Schema

Formal schema documentation for the constrained, deterministic JSON UI specification generated by on-device models.

**Author: Priyan**  
**Track: Developer Tools (iQOO Hackathon 2026 Grand Finale)**  
**Status: Documentation and Specification (No code files)**

---

## 1. Design Philosophy

Small on-device language models (1.5B–2B parameters) frequently hallucinate syntax, invent non-existent APIs, or produce broken component closures when tasked with writing free-form React, Vue, or Flutter code.

SketchCode eliminates this failure class entirely:
- **No Arbitrary Code Generation**: The local model never writes JavaScript, JSX, or CSS.
- **Strict Grammatical Envelope**: The model generates an abstract UI spec adhering strictly to a closed component vocabulary.
- **Deterministic Interpretation**: A fixed client-side React engine renders the spec. Any malformed or unsupported property is ignored safely.

---

## 2. Root Spec Structure

Every SketchCode project is represented as a single top-level JSON document containing one or more screens.

```json
{
  "$schema": "https://sketchcode.dev/schemas/v1/ui-spec.json",
  "appName": "Grocery Quick",
  "version": "1.0.0",
  "initialScreen": "screen_main",
  "theme": {
    "primaryColor": "#FFB300",
    "mode": "dark"
  },
  "screens": []
}
```

### Top-Level Properties

| Property | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `appName` | `string` | Yes | Human-readable name of the application. |
| `version` | `string` | Yes | Specification semantic version (must be `"1.0.0"`). |
| `initialScreen` | `string` | Yes | ID of the screen loaded on startup. Must exist in `screens`. |
| `theme` | `object` | No | Palette overrides (`primaryColor`, `mode`: `"dark"` or `"light"`). |
| `screens` | `array` | Yes | Non-empty array of `screen` objects. |

## 3. Allowed Component Types

SketchCode restricts UI elements to seven standard mobile components:

```
screen -> [ navbar, text, input, button, list, image ]
```

### 3.1 `screen`
Top-level mobile view container.

| Property | Type | Description |
| :--- | :--- | :--- |
| `id` | `string` (unique) | Unique identifier for screen routing (e.g., `"screen_main"`). |
| `title` | `string` | View title displayed on navigation bars. |
| `components` | `array` | Ordered list of child components rendered vertically. |

### 3.2 `navbar`
Fixed header or tab bar.

| Property | Type | Description |
| :--- | :--- | :--- |
| `type` | `"navbar"` | Component identifier. |
| `title` | `string` | Header title. |
| `showBackButton` | `boolean` | Renders a back button that returns to the previous screen. |
| `tabs` | `array` (optional) | Array of `{ "id": string, "label": string, "targetScreen": string }`. |

### 3.3 `text`
Typography primitive for headings, subtitles, and captions.

| Property | Type | Description |
| :--- | :--- | :--- |
| `type` | `"text"` | Component identifier. |
| `value` | `string` | Text string to display. |
| `variant` | `"h1"` \| `"h2"` \| `"body"` \| `"caption"` | Visual typographic role. |
| `color` | `"default"` \| `"muted"` \| `"accent"` | Text coloring token. |

### 3.4 `input`
Interactive single-line or multi-line text field.

| Property | Type | Description |
| :--- | :--- | :--- |
| `type` | `"input"` | Component identifier. |
| `id` | `string` (unique) | State key holding the input value (e.g., `"new_item_title"`). |
| `placeholder` | `string` | Hint text displayed when input is empty. |
| `inputType` | `"text"` \| `"number"` \| `"search"` | Keyboard behavior trigger on mobile. |

### 3.5 `button`
Tappable action component triggering deterministic state mutations.

| Property | Type | Description |
| :--- | :--- | :--- |
| `type` | `"button"` | Component identifier. |
| `label` | `string` | Visible button text. |
| `variant` | `"primary"` \| `"secondary"` \| `"danger"` | Visual styling role. |
| `action` | `object` | Action descriptor (see Section 4). |

### 3.6 `list`
Dynamic or static collection of vertical row items.

| Property | Type | Description |
| :--- | :--- | :--- |
| `type` | `"list"` | Component identifier. |
| `id` | `string` (unique) | State identifier for items (e.g., `"todo_items"`). |
| `emptyStateMessage` | `string` | Message displayed when list has 0 items. |
| `itemTemplate` | `object` | Defines item fields: `{ "showCheckbox": true, "showDelete": true }`. |
| `initialItems` | `array` | Optional list of default strings or records. |

### 3.7 `image`
Graphic element displaying a system icon, placeholder, or generated SVG.

| Property | Type | Description |
| :--- | :--- | :--- |
| `type` | `"image"` | Component identifier. |
| `iconName` | `string` | Name of standard Feather/Lucide icon (e.g., `"shopping-cart"`, `"coffee"`). |
| `alt` | `string` | Accessibility label. |

## 4. Deterministic Action Model

To preserve safety and eliminate security vulnerabilities, buttons trigger only predefined actions. Arbitrary JavaScript execution is prohibited.

| Action Type | Required Parameters | Behavior |
| :--- | :--- | :--- |
| `"navigate"` | `targetScreen`: string | Switches the viewport to the target screen. |
| `"add_to_list"` | `targetListId`: string, `sourceInputId`: string | Reads text from the input, appends a new item to the list, clears the input. |
| `"delete_from_list"` | `targetListId`: string | Deletes the targeted row item. |
| `"toggle_item"` | `targetListId`: string | Toggles the completion checkbox on a list row. |
| `"show_toast"` | `message`: string | Displays a temporary informational banner. |

---

## 5. Validation and Sanitization Rules

Before rendering, the JSON payload passes through an AST sanitizer:

1. **Schema Integrity**: Unknown properties are discarded silently without failing the build.
2. **Key Uniqueness**: All component `id` values must be unique within the screen; collisions are automatically suffixed with random integers.
3. **Route Verification**: If `initialScreen` or a navigation `targetScreen` is missing from `screens`, the first valid screen is substituted as fallback.
4. **Depth Bounds**: Spec nesting is capped at 4 levels deep to protect memory buffers.
5. **String Sanitization**: All displayed text is sanitized against HTML/XSS injection.

## 6. Illustrative Example 1: Grocery Quick (List App)

This is the exact JSON specification output from the sample sketch and Tamil/English voice prompt depicted in the project wireframes.

```json
{
  "$schema": "https://sketchcode.dev/schemas/v1/ui-spec.json",
  "appName": "Grocery Quick",
  "version": "1.0.0",
  "initialScreen": "screen_main",
  "theme": {
    "primaryColor": "#FFB300",
    "mode": "dark"
  },
  "screens": [
    {
      "id": "screen_main",
      "title": "Grocery Quick",
      "components": [
        {
          "type": "navbar",
          "title": "Grocery Quick",
          "showBackButton": false
        },
        {
          "type": "text",
          "value": "Add Grocery Item",
          "variant": "caption",
          "color": "muted"
        },
        {
          "type": "input",
          "id": "grocery_input",
          "placeholder": "e.g., Cooking Oil 1L",
          "inputType": "text"
        },
        {
          "type": "button",
          "label": "+ Add to List",
          "variant": "primary",
          "action": {
            "type": "add_to_list",
            "targetListId": "grocery_list",
            "sourceInputId": "grocery_input"
          }
        },
        {
          "type": "text",
          "value": "Current List",
          "variant": "h2",
          "color": "default"
        },
        {
          "type": "list",
          "id": "grocery_list",
          "emptyStateMessage": "No items added yet. Sketch or type to add!",
          "itemTemplate": {
            "showCheckbox": true,
            "showDelete": true
          },
          "initialItems": [
            "Fresh Milk (Aavin 500ml)",
            "Brown Eggs (6 pcs)",
            "Bananas (1 kg)"
          ]
        }
      ]
    }
  ]
}
```
